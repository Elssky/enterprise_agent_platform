# Part V Agent 能力百科 · 优化导读

Part V 讨论的是 Agent 真正进入生产后必须具备的运行能力。十章看似分别讲 Runtime、工具、MCP、Planner、Memory、多 Agent、HITL 和框架，实际上围绕同一条主线展开：**模型可以负责提出不确定决策，但状态、权限、副作用和责任证据必须由平台掌握。**

![Part V Agent 能力百科整体架构](../../images/part5/ch/p5-00-part-overview-architecture.png)

## 本部分的核心结构

| 章 | 核心问题 | 最重要的工程边界 |
|---|---|---|
| 第22章 Agent Runtime | 一次任务怎样执行、暂停、恢复 | Planner 提议，Runtime 掌握状态与执行权 |
| 第23章 Tool Registry | 工具怎样进入生产 | Function Calling 是意图，Registry 是执行契约 |
| 第24章 MCP | 外部工具怎样标准接入 | MCP 不替代 Registry、IAM 和 Policy |
| 第25章 Planner | 下一步怎样决策 | Planner 决策与 Runtime 执行分离 |
| 第26章 Agentic Workflow | 反思/精炼/搜索怎样受控 | 增强默认有界、可关闭、不可扩大执行权 |
| 第27章 Memory | 什么值得被记住 | 不同生命周期分层，长期写入需准入和删除 |
| 第28章 多 Agent | 什么时候拆角色 | 职责分离但保持同一 Run 与 Handoff 契约 |
| 第29章 协议标准 | MCP/A2A 等怎样共存 | 协议变化停在适配层，内部运行模型稳定 |
| 第30章 HITL 与长任务 | 人和长任务怎样进入状态机 | 人工承担责任，审批绑定具体版本和证据 |
| 第31章 框架对标 | 开源/低代码/自研怎样组合 | 框架加速表达，企业平台接管生产责任 |

## 推荐阅读路径

如果只想先掌握最关键的生产骨架，优先阅读 **22 → 23 → 25 → 30**：先理解 Run，再理解工具执行权、Planner 边界和人工责任。

随后阅读 **24 → 27 → 29**，处理外部工具、上下文和协议；最后阅读 **26 → 28 → 31**，判断什么时候值得增加反思、多 Agent 或外部框架复杂度。

## 本部分统一判断

Part V 最容易出现的误区，是把更多自治能力直接等同于更成熟的平台：更多 Tool、更多 Agent、更深反思、更多协议和更多框架都可以让 Demo 更丰富，却会同时扩大执行面。

**成熟度真正来自“边界稳定”：一次 Run 里，谁可以决策、谁可以执行、什么上下文可以使用、哪一步需要人工、失败后由谁恢复，都有结构化契约和证据。**

`mini-platform/projects/multi-agent-workflow/` 可以作为这一部分的统一实战入口。重点不是某个示例能否跑通，而是不同能力最终是否仍然落在同一个 `run_id`、Registry、checkpoint 和 Trace 上。
